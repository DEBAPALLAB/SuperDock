# SuperDock privacy

SuperDock has no accounts, analytics, advertising SDK, or crash uploader. It
checks the official public GitHub Releases feed once per day for a newer version.
You can also check manually from the tray menu. This request contains no
personal data or device identifier. SuperDock downloads nothing until you choose
an update; it then downloads the official installer and verifies its SHA-256
checksum before offering to restart and install it. GitHub may receive your IP
address as part of normal HTTPS traffic. No usage telemetry is sent.

Notes, reminders, preferences, and a local startup/graphics diagnostic log stay
on this PC. The app reads Windows media-session metadata and artwork to display
and control the current player. The Sound widget reads and changes the selected
Windows audio output's volume and mute state.

Liquid glass uses Windows Desktop Duplication to sample display pixels on the
GPU and refract the small area behind the notch. Those pixels are not read by
the CPU, recorded, saved, or uploaded. SuperDock excludes itself from screen
captures to prevent the lens from sampling itself. Disable **Liquid glass** in
the context menu to stop sampling and include the dock in recordings again.

File-shelf entries reference files you drop onto the app. Removing a shelf
reference does not delete the original. Copy and paste only access the clipboard
when you request those actions; the app does not collect clipboard history.

Choosing Browser opens a website in your default browser. Apps launched from
SuperDock, Windows services, your browser, and your media player have their own
network behavior and privacy policies.

Data is normally stored in `%LOCALAPPDATA%\SuperDock`. Open the data folder
from the app's context menu. Uninstall preserves notes and reminders. To remove
them, exit the app and remove that folder yourself.

Existing development-build users may continue using their original
`%LOCALAPPDATA%\UniDock` or `%LOCALAPPDATA%\NotchDock` folder so their notes and
preferences stay available.

Support reports are manual. Avoid posting notes, reminders, media history,
personal file paths, or unreviewed screenshots in public bug reports.
